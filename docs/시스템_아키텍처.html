CECO 데모 시스템 구조

반응 공정 한 줄을 가상으로 돌리고, 공장(OT)·완충지대(DMZ)·사무(IT) 세 구역으로 나눠 계측 → 이상 탐지 → 경보 → AI 대응 → 승인된 작업 요청 → 설비 반영까지 한 번에 보여 주는 학생 수준의 산출물 예시다. 모든 부품은 무료 공개 제품이고 도커 컴포즈 한 벌로 뜬다.

그림의 부품 36개와 선 49개에 번호를 붙였다. 아래 본문의 같은 번호가 같은 것을 가리킨다.

그림 읽는 법전체 그림구역과 연결 원칙네 흐름부품 36개선 49개줄이거나 고른 것

그림 읽는 법

● 이 쪽이 연결을 연다(TCP를 먼저 건다).
화살표 데이터가 흐르는 방향. 양쪽 끝에 있으면 오고 간다.
빨간 굵은 선 작업 요청 길. 검사 1·2·3은 요청을 거르는 세 겹(게이트웨이 → OT 수신기 → PLC).
회색 점선 감시 지표. 공정 데이터는 싣지 않는다.
긴 점선 기동 때 한 번 도는 도우미, 파일 전달. 점선 상자가 도우미다.
상자 위 작은 회색 표 감시 지표를 긁는 선. 선을 그리지 않고 긁는 쪽(“긁음”)과 대상에 같은 번호를 붙였다.
검은 막대 구역 라우터. 막대 위 숫자는 라우터가 넘겨 주는 포트.

전체 그림

좁은 화면에서는 그림을 옆으로 밀어 본다. 한 선이 여러 곳으로 갈라지면(부채꼴) 번호는 하나다.

구역과 연결 원칙

OT · 공장 망

2~8, 33(현장 1과 붙어 있다). 기계와 가까운 부품. 밖과 연결이 끊겨도 계측·화면·제어·안전이 그대로 돈다. 공장 안 부품은 모두 4에만 연결한다.

DMZ · 완충 망

10~14. 공장과 사무가 직접 만나지 않고 여기서만 주고받는다. DMZ 부품은 어느 쪽으로도 새 연결을 열지 않는다.

IT · 사무 망

15~30과 도우미. 분석·기록·AI·업무. 공장에는 요청만 보낼 수 있고, 그것도 DMZ 게이트웨이를 거친다.

  1. 연결은 신뢰가 높은 쪽이 연다. OT → DMZ는 L9·L11 두 가지뿐이고, IT → DMZ는 L16·L17(같은 계정), L18, L19·L20, L21이다.
  2. DMZ → OT, DMZ → IT, IT → OT로 새 연결은 없다. 9 구역 라우터가 허용 목록 밖을 세고 버리며, 응답은 이미 열린 연결로만 돌아간다.
  3. DMZ의 요청이 OT로 들어오는 것도 OT가 연 브리지 L10으로 가져오는 방식이다. 연결 방향(●)과 데이터 방향(화살표)이 다를 수 있어 그림에 둘을 따로 표시했다.
  4. MQTT 계정마다 읽기·쓰기 토픽을 ACL로 좁혔다. 예: IT 수집기는 DMZ에서 표시 토픽 하나에만 쓸 수 있다.

네 흐름

번호 순서대로 따라가면 된다. 동그라미 숫자는 부품, L 숫자는 선이다.

흐름 1 · 계측: 현장 값이 화면과 기록까지

  1. 1 가상설비이 물리 계산으로 값을 만든다. 2 PLC가 L1으로 100 ms마다 읽는다.
  2. 3 엣지 게이트웨이가 L2으로 250 ms마다 두 블록을 읽고, 새 스캔일 때만 UNS 토픽(값·품질·출처 시각 ns·스캔 순번)으로 L3를 거쳐 4 OT 허브에 낸다.
  3. 5 운전원 화면가 L5로 같은 값을 받아 화면에 보이고 공정 알람을 판정한다. 여기까지는 공장 안이라 DMZ가 끊겨도 돈다.
  4. 4 OT 허브가 연 브리지 L9로 값이 10 DMZ 브로커에 올라간다. 라우터 1883만 열려 있다.
  5. 11 DMZ 적재기가 L12로 받아 L13로 12 DMZ 원시 사본에 적는다(7일, 결측은 공백).
  6. 16 IT 수집기 스트림 ①이 L16로 같은 값을 가져가 L22로 Kafka sensor.telemetry.raw(키 = 설비)와 plant.status에 쓴다.
  7. 17 Flink가 L23로 raw를 읽어 보간한 clean, 이상 점수, alert를 다시 Kafka에 쓴다.
  8. 16 IT 수집기 스트림 ②가 결과를 L25로 20 IT 결과 저장에 적고, 22 Grafana가 L37와 L19로 그린다.

흐름 2 · 경보: 이상을 찾아 묶고 화면과 AI로

  1. 17 Flink가 규칙·Z-Score·CEP·오토인코더로 이상을 찾아 L23로 sensor.alerts에 쓴다.
  2. 16 IT 수집기 스트림 ④가 alert를 라벨(설비·규칙)을 붙여 L26로 24 Alertmanager에 넣는다. 스트림 ⑤는 plant.status에서 정비 모드·PLC 정지·설비 꺼짐을 억제 상태로 넣는다.
  3. 24 Alertmanager이 (설비, 규칙)으로 묶고 억제 규칙을 적용한 뒤, 새 묶음·해제만 L27로 알린다.
  4. 16 IT 수집기 스트림 ⑥이 L28로 21 업무 DB에 묶음(ACTIVE/CLEARED)과 사건(DISPLAYED · OUT_OF_SERVICE · SUPPRESSED_BY_DESIGN)을 적고, 새 묶음만 Kafka alerts.display로 낸다.
  5. 16 IT 수집기 스트림 ③이 L17로 10 DMZ 브로커의 AR-100/alert/display에 쓰고, 허브 브리지 L10이 그것을 공장 안으로 가져간다.
  6. 5 운전원 화면가 L5로 받아 '분석 경고(참고)'에 보인다. 공정 알람과 따로 보인다.
  7. 같은 sensor.alerts를 30 업무 서비스가 L29로 읽어 AI 사건으로 접수한다(L30). 28 AI 업무 도우미가 사건을 연다.

흐름 3 · 작업 요청: 승인된 요청이 설비에 닿고 결과가 돌아오기까지

  1. 28 AI 업무 도우미에서 사람이 대응안을 승인하면, 요청 한 건과 승인 사건·감사를 L31로 21 업무 DB에 적는다(요청자 ai-ops, 종류 ai). MES 흉내는 L45로 16 IT 수집기 스트림 ⑧에 지시를 넣고, 같은 방식으로 적힌다(mes-01, 종류 mes, 승인자 planner-01).
  2. 기록이 끝나면 요청 ID를 L32로 Kafka request.approved에 낸다(스트림 ⑧은 L22로 낸다).
  3. 16 IT 수집기 스트림 ⑦이 승인 토픽을 읽고, 마지막 사건이 approved인 요청만 dispatched를 먼저 적은 뒤 L18로 13 DMZ 요청 게이트웨이에 POST한다. 같은 승인이 다시 와도 다시 보내지 않는다.
  4. 검사 1 · 13 DMZ 요청 게이트웨이가 토큰·스키마·허용 작업·범위·요청자 ID와 종류·승인자·나이·중복을 본다. 거부면 이유를 바로 돌려주고, 통과면 L14로 10 DMZ 브로커에 올린 뒤 202와 만료 시각을 돌려준다. 스트림 ⑦이 이것을 첫 응답 ⓐ로 적는다.
  5. 4 OT 허브의 브리지 L10이 요청을 공장 안으로 가져온다. 30초가 지나면 브로커가 스스로 버린다.
  6. 검사 2 · 3 엣지 게이트웨이의 OT 수신기 탭이 L4로 받아 스키마를 다시 보고, PLC 모드·정비·만료로 받을지 정한다. REMOTE_AUTO면 바로 명령, REMOTE_MANUAL이면 5 운전원 화면 받은 요청 목록에 올려 운전원을 60초 기다린다. 결정은 응답 ⓑ로 낸다.
  7. 검사 3 · 엣지가 L2로 PLC 외부 요청 채널에 코드·값·만료·해시를 쓴다. 2 PLC가 모드·인터록·범위·만료를 다시 보고 수용·거부 ACK를 낸다(응답 ⓒ).
  8. 응답 ⓑⓒ는 L9 → L16 → Kafka request.responses → 30 업무 서비스로 가서 21 업무 DB에 적힌다. 30 업무 서비스가 PLC 수용 뒤 10초 안에 설비 상태가 바뀌었는지 재관측한다(observed / command_disagree). 28 AI 업무 도우미는 이 사건을 읽기만 한다.
  9. 실측(2026-09-30, REMOTE_AUTO 온도 설정 요청): 승인 0 s → dispatched 0.01 → 게이트웨이 수용 0.03 → OT 수신 0.25 → PLC 수용 0.26 → 재관측 일치 0.46 s.

흐름 4 · 운전원 조작: 화면 버튼이 기계를 움직이기까지

  1. 사람이 L43로 6 화면 관문에 계정을 대고 들어오면, 관문이 L6로 5 운전원 화면 화면을 넘긴다.
  2. 운전원이 버튼을 누르면 5 운전원 화면가 L5로 …/cmd/operator에 명령(코드·값)을 낸다.
  3. 3 엣지 게이트웨이 수집·명령 탭이 L3로 받아 L2로 PLC 운전원 채널에 코드·값을 쓰고 순번을 올린다.
  4. 2 PLC가 모드(REMOTE_AUTO면 운전원 조작 거부)·정비·인터록·범위를 보고 수용·거부 ACK를 내고, 수용이면 L1으로 기계를 움직인다.
  5. ACK와 새 값이 흐름 1의 길로 5 운전원 화면에 돌아와 화면이 바뀐다. 고압 인터록이 걸리면 펌프가 멈추고, 운전원이 1 가상설비 현장 패널 또는 화면에서 리셋해야 풀린다.

현장

PLC

OT

OpenPLC Runtime v4.2.4

기계 바로 옆의 제어기. 100 ms 주기로 가상설비를 읽고 쓴다. 운전 모드(LOCAL · REMOTE_MANUAL · REMOTE_AUTO)와 정비 모드, 고압 인터록(PT-101 6.5 barg에서 펌프 정지, 운전원이 리셋해야 풀림), 설정값 범위, 건조 운전 방지를 여기서 지킨다. 운전원 명령 채널과 외부 요청 채널을 따로 받고, 외부 요청은 만료 시각·요청 해시까지 확인한다(검사 3).

엣지 게이트웨이

OT

Node-RED 5.0.7 · 수집·명령 탭 + OT 수신기 탭

Node-RED 한 개에 탭 두 개. 수집·명령 탭은 PLC를 250 ms마다 두 블록으로 읽어 UNS 토픽(품질·출처 시각·스캔 순번 포함)으로 내고, 운전원·외부 요청 명령을 PLC 채널에 쓴다. 끊기면 디스크에 모아 두었다가 다시 보낸다. OT 수신기 탭은 밖에서 온 작업 요청을 스키마로 다시 검사하고 PLC 모드·정비·만료를 보고 받을지 정한다(검사 2): REMOTE_AUTO면 바로 명령, REMOTE_MANUAL이면 운전원 대기 60초, 그 밖은 거부. 편집기는 로그인해도 읽기 전용이다. 흐름은 등록부에서 생성해 기동마다 다시 배포한다.

줄이거나 고른 것

  • 세 구역은 망 세 개와 라우터 규칙 9로 흉내 냈다. 실제 공장은 방화벽 장비(응용 계층 검사 포함)를 둔다.
  • 브리지는 연결 하나로 양방향(L9·L10)이고, TLS와 강한 인증은 뺐다. 2026 연결 원칙은 DMZ 복제에 단방향·강한 인증을 권한다(교육용 축소).
  • IT는 DMZ 원시 사본 12을 조회하고, DMZ 브로커 10도 직접 구독한다. 지침은 DMZ 히스토리언을 강한 인증 HTTPS API로 조회하라고 권한다.
  • MQTT 브로커를 두 개(4·10) 둔 것은 공장 화면이 DMZ 없이도 돌아야 한다는 격리 원칙 때문이다. 현업에는 DMZ 브로커 하나에 공장이 밖으로 접속하는 방식도 흔하다.
  • REMOTE_AUTO 자동 수용은 "분석 시스템은 관찰만 하고 운전을 바꾸지 않는다"는 2026 지침 문장과 부딪힌다. 검증을 거친 자동 반영을 허용하는 NAMUR NE 178 쪽을 택했고, 안전(인터록·범위·되읽기)은 PLC 2가 지킨다.
  • DMZ에 원시값을 7일 저장한다. "DMZ는 데이터를 영구 저장하지 않는다"는 Cisco CPwE와 달리 DMZ 히스토리언을 두는 2026 지침 쪽을 택했다.
  • 대시보드를 IT에 둔 것은 지침에 없는 우리 판단이다. 운전원 화면 5는 공장 안에 둔다.
  • 작업 요청을 보내는 외부 시스템은 AI(28)와 MES 흉내(16 스트림 ⑧) 둘이다. 요청 필드(job_order_id·work_master_id)는 ISA-95 작업 지시를 흉내 냈고, 만료 필드는 표준에 없는 확장이다.
