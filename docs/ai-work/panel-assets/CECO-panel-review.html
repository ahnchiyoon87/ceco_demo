제조 AI 업무도우미
패널 원고와 실제 화면

온톨로지로 설비·센서·문서를 연결하고, AI 대응안을 사람이 검토하는 제조 업무도우미입니다.

2026.09.21 검토본 · 교육용 가상 공정의 강사 시연본입니다. 아래 두 화면은 실행 중인 서비스에서 직접 캡처했습니다. 전체 UI 리허설과 AI 검토·결과 화면의 최종 캡처는 남아 있습니다.

비전 및 목표

작품명: 온톨로지 기반 제조 AI 업무도우미

기존 IIoT·SCADA에서 교반기 이상 알람을 받으면, 관련 센서 이력과 설비 정보, 대응 문서를 연결해 보여준다. AI가 관측 사실과 미확인 원인, 필요한 점검을 정리하고 사용자가 대응안을 검토한다. 승인된 시뮬레이터 조치는 후속 관측으로 결과를 확인하고 기록한다.

비전: 제조 알람 이후 여러 화면과 문서를 찾아야 하는 부담을 줄이고, 작업자가 근거를 확인하며 대응을 결정할 수 있는 업무 환경을 제공한다.

목표: 센서·설비·문서를 온톨로지와 그래프 DB로 연결하고, AI 근거 조회·대응안 작성·사용자 승인과 반려·조치 결과 확인을 하나의 제조 업무 흐름으로 구현한다. 실제 공장을 대신하는 가상 반응기 AR-100에서 시연한다.

성과 등 주요내용

작동 흐름

가상 교반기 이상 발생 → SCADA 알람 수신·사건 생성 → 센서 이력·설비 관계·적용 문서 조회 → AI 대응안 작성 → 사용자 승인 또는 반려 → 승인 조건 재확인 → 시뮬레이터 조치 → 새 관측으로 결과 확인·후속 점검 기록

주요 기능

• 전류·진동 관련 반복 알람을 대응 사건으로 묶고 원본 알람과 발생 시각을 보존한다.

• 설비 설정과 문서에서 구조·관계 후보를 만들고, 출처와 적용 대상을 검토해 그래프에 게시한다. 설비–센서–대응 문서를 연결해 탐색한다.

• AI가 사건 당시 이력과 현재 관측을 구분하고 문서 근거, 원인 후보, 미확인 항목을 정리한다. 문서 누락·충돌·관측 품질 문제를 확인할 내용으로 남긴다.

• 승인 전에는 제어 명령을 보내지 않는다. 승인 시 현재 상태와 근거를 다시 확인하며, 반려 사유와 처리 결과도 기록한다. 정지 확인과 정비 완료를 구분한다.

시스템 구성

• 기존 IIoT·SCADA: 가상 반응기 센서·제어, 데이터 수집, 규칙 기반 이상 감지, 시계열 이력 저장.

• 온톨로지·Neo4j: 설비·센서·문서 관계, 문서 버전과 출처, 적용 절차 조회.

• AI 업무 계층: LiteLLM 중계의 루나 모델이 알람·관측·문서 도구를 조회하고 검토 가능한 대응안을 작성. PostgreSQL에 사건·분석·검토·결과를 보존.

• 통합 웹 화면: 사건 현황, 근거와 추세, 지식 구축·관계 탐색, 검토와 처리 결과를 한 제품에서 제공. Process GPT와 Ontology Studio의 필요한 코드를 선별·리팩토링해 내부에 통합.

관람객 체험

강사가 가상 이상 상황을 시작하면 관람객은 작업자 역할로 사건을 선택한다. 전류·진동 추세와 연결된 대응 문서를 살펴보고 AI 대응안의 근거와 미확인 항목을 확인한다. 승인 또는 반려에 따라 달라지는 처리 흐름을 관찰하고, 정지한 경우 후속 관측과 남은 점검 항목을 확인한다. 관람객의 실제 화면 조작 동선은 리허설 후 확정한다.

성과 확인

실제 알람 수신, 그래프의 설비·문서 연결, 루나의 도구 조회와 대응안 생성, 사용자 검토, 시뮬레이터 정지와 후속 관측까지의 기록으로 동작을 확인한다. 문서 부족·충돌, 불량 관측, 모델 연결 실패에서도 근거 없는 자동 실행이 발생하지 않는지 함께 검증한다. 업무시간 절감률이나 예지보전 정확도는 측정 전 수치로 제시하지 않는다.

전시 운영

시작 전 가상 공정과 교육용 문서임을 안내한다. 정지·복구는 시뮬레이터 범위에서 강사 관리하에 수행한다. 시연 종료 후 고장 주입과 운전 상태를 확인해 다음 체험을 준비한다. 통신 실패나 결과 불명확 상태에서는 명령을 자동 반복하지 않고 기록과 현재 상태를 확인한다.
