# 교반기 전류·진동 이상 대응

이 문서는 AR-100 가상 공정의 교육·전시용 대응 절차다. 실물 장비의 운전 승인 문서가 아니다. M-101이 특정 제조사 제품이라는 가정은 하지 않는다.

## 1. 사건을 확인한다

동일 시간대의 IT-102 전류와 VT-101 진동 알람을 확인한다. CEP_BEARING은 전류 9.6 A 초과 후 10초 이내 진동 7.1 mm/s 초과를 감지하는 기존 Flink 규칙이다. 이 값은 프로젝트 설정이며 제조사 공통 허용치가 아니다. 규칙의 '베어링 열화 의심'은 가설로 표시한다.

상관 처리로 묶인 알람의 원문·발생시간·감지기를 열람할 수 있어야 한다. ML_AUTOENCODER는 원인 확인 전까지 별도 신호로 취급한다.

## 2. 근거 자료를 확인한다

1. 발생 전후 IT-102/VT-101 이력을 조회한다. 조회 구간·단위·관측시간·quality를 표시한다.
2. 현재 교반기 기동 상태와 LT-102 반응기 액위를 확인한다. 액위는 관련 운전 맥락이며, 낮은 액위가 이번 사건의 원인이라는 결론은 별도 근거가 필요하다.
3. 결측·보간·오래된 값이면 관측 한계를 먼저 표시한다. 보간값을 실제 측정값으로 제시하지 않는다.
4. 축 정렬·베어링 실물 상태·윤활 상태·실제 점도는 현재 센서로 확인되지 않는다. 이 항목은 미확인으로 남기고 현장 점검 요청에 포함한다.

제조사 참고: INOXPA BCI 매뉴얼 20.005.30.01EN, (B) 2024/08, p.15는 진동/소음에 액위 부족, 축 변형, 임계 속도, 베어링 마모 등 복수 후보를 제시한다. 이를 '원인 후보를 구분하고 근거를 더 확인한다'는 원리에만 참고한다. BCI 사양·정비 조치·운전 제한을 AR-100에 그대로 적용하지 않는다.

## 3. 대응안을 작성한다

AI는 관측 사실, 원인 후보, 미확인 항목, 제안 행동, 출처를 구분한다. 실행 가능한 제안은 이 시연에서 허용한 시뮬레이터 명령으로 제한한다. 실제 장비 분해·윤활·부품 교체를 완료했다고 작성하지 않는다.

교반기 정지를 제안할 경우 사건 ID·설비·명령·현재 상태·근거와 예상 확인 방법을 함께 제시한다. 근거가 부족하면 추가 확인 요청으로 진행한다. 긴급 인터록은 기존 SCADA 로직이 담당하며 AI의 응답·승인을 기다리도록 바꾸지 않는다.

## 4. 검토와 조치

검토자는 승인·반려·추가 확인을 선택한다. 반려에는 이유를 남긴다. 승인 당시의 사건 revision과 실제 실행 직전 상태를 대조한다. 승인한 대상·행동이 달라졌거나 상태가 바뀌면 재검토한다.

정지 명령 전송 성공만으로 작업을 완료하지 않는다. 통신 오류·타임아웃이면 결과 불명확 상태로 두고 재조회한다. 이미 전송됐을 수 있는 명령을 자동 반복하지 않는다.

## 5. 결과와 인수인계

기동 상태와 후속 관측으로 '정지 확인' 여부를 기록한다. 정지 후 전류·진동 감소는 수리 완료의 증거가 아니다. 시뮬레이터 고장 주입은 시간 만료 또는 clear로 해제될 수 있으므로 자연 복귀와 조치 결과를 구분한다.

최종 기록: 관측 근거, 검토자 결정, 요청 명령, 확인된 결과, 미해결 점검 항목. 실제 베어링 정비가 필요한지는 이 시뮬레이션만으로 확정하지 않는다.
