IIoT·SCADA 실습 시스템 — 현업 기준 프로토타입 확정과 검증

오늘은 학생 실습 시스템의 원본(V1)에서 출발해 여러 번의 회전을 거쳐 2026년 제조 현업과 같은 구조·흐름·스택의 프로토타입을 확정했다. 확정안대로 조립하고 원본과 같은 방법으로 검증까지 마쳤다. 아래는 그 과정을 순서대로 담았다: 무엇을 기준으로 조사했고, 현업은 어떻게 하고, 그래서 우리는 무엇을 왜 골랐는지.

  1. 원본 다시 재기빠르게 도는 가상설비(배속 600)로 원본의 성능·복구 기준값을 다시 쟀다.
  2. 경량화 실험가볍게 줄인 판(V2)을 만들어 봤지만 층을 빼는 데모식이라 현업과 멀어져 접었다.
  3. 방향 전환"현업이 실제로 쓰는 구조·흐름·스택"을 기준으로 다시 잡았다.
  4. 조사 다섯 건구조·세부·스택·무료 대체품·외부 연결을 조사하고, 설계 판단 70개를 표준·사례와 하나씩 대조했다.
  5. 조립·검증확정안대로 조립하고 원본과 같은 방법으로 쟀다. 합격선 항목은 모두 원본과 같거나 나았고, CPU만 3.6 %p 높았다(10장).

1. 어떤 기준으로 조사했나

목표는 경남대 제조 AI 과정 학생이 각자 PC 한 대에서 돌리는 IIoT·SCADA 실습 시스템을 2026년 제조 현업과 똑같은 구조·흐름·스택으로 만드는 것이다. 현업을 그대로 옮길 수는 없어서 칸마다 아래 순서로 걸렀다.

  1. ①
    현업에서 주로 쓰는가표준·공공 지침·독립 분석·설문에 나온 주류. 무료 본체가 있으면 그대로 쓴다.
  2. ②
    관문을 통과하는가비용 0 · 상용·제한형 라이선스 아님(BSL·SSPL·TSL·RCL·체험판·상용 전용 기능) · 공식 도커 이미지가 있고 PC 한 대(도커 약 7.6 GB)에서 돈다 · 제품 계열이 계속 개발된다. 판마다 있는 지원 종료일은 제외 이유가 아니다(학기마다 최신 판으로 올림).
  3. ③
    가볍게 할 수 있는가현업 수준을 유지한 채 가벼운 판·설정·중복 합치기로 줄인다. 층을 빼지 않는다.

구조와 흐름은 적용되는 규칙(법령·표준·공공 지침)이 있으면 따르고, 없으면 현업이 흔히 하는 방식을 따른다.

데이터 ↑ 설비 → 제어기(PLC) → 엣지(프로토콜 변환, 끊기면 저장 후 전송) → MQTT 허브(UNS, 공장/구역/라인/설비 이름 체계) → DMZ에서 위로 복제 → Kafka형 장부·이력 저장 → 분석·대시보드·AI(OT가 밀어낸 데이터를 읽기만). 주기 샘플링과 변화 필터, 값마다 시각과 품질(끊기면 STALE).
명령 ↓ 운전원은 SCADA 화면 → 제어기. 외부·AI 명령은 사람 승인 → DMZ 검증 통로 → 공장 안에서 받을지 정하고 제어기가 물리적으로 되는지 판단(2026 공동 지침 p.25, OPC UA Job Control). 확인은 제어기 응답과 바뀐 값 두 겹. IT에서 OT로 바로 가는 길은 없다.
알람 공정 알람은 제어기·SCADA가 만들고 수명주기(인지·억제)를 가진다. 분석 결과는 ISA-18.2의 "경고(alert)"로 알람 목록과 따로 둔다. 서버·컨테이너 경보는 인프라 담당에게만 간다.
AI 위치 현업에 "AI 층"은 따로 없다. ML 이상 탐지는 주로 L1~L3(PLC·엣지·SCADA 쪽), LLM·에이전트는 L4~5(OT 밖)에서 OT가 브로커·감사되는 버퍼로 내보낸 데이터를 읽기 전용으로 쓴다(CISA 등 9개 기관 AI-OT 지침 2025 표1·p.15·p.19). "Kafka를 거쳐 AI로"는 이 원칙과 UNS+Kafka 트렌드를 합친 구성이고, 표준이 제품을 지목하지는 않는다. 지식 그래프·LLM 에이전트의 현장 운영 비율은 설문 수치가 없다.
저장 현업 권장 배치는 사이트 히스토리언(OT L3) + DMZ 복제이고, 외부는 DMZ 사본을 조회한다(CISA 2016, 2026 공동 지침 p.19). 명령·승인·감사 기록은 추가만 하고 무단 수정·삭제를 막는다(보존 기간은 조직이 정함).
설비 추가 층은 그대로. 설비 종류 모델과 설비 목록(등록부)에 더하면 이름·토픽·키·규칙이 같은 ID로 이어진다.
