## 2. 시나리오별 흐름

### 시나리오 1 — 반응기 온도 상승(냉각수 계통)
1. 강사 화면 "시나리오 1 · 이상 발생" (스트레이너 막힘). 수 초 안에 반응기 온도가 95 °C 상한을 넘는다.
2. AI 화면에 "반응기 온도 상승 · 냉각 계통" 사건 → 약 1~1.5분 뒤 조치 카드.
3. 카드에서 짚을 것: 원인 판단 표(유량 2.5 m³/h·차압 1.7 bar·냉각수 온도차 41 °C → 스트레이너 지지, 나머지 반박), 대안 손익표(온라인 전환 −25만원 1위, "감속 버티기"는 규칙으로 제외), 뒤집힘 조건.
4. 승인 → 정비팀이 예비 바스켓 전환·막힌 바스켓 세척(소견 "이물 다량") → 온도 107 → 70 °C, 30초 유지 → 작업 보고서.

**변형(재킷 스케일)** — 같은 온도 상승인데 유량·차압은 정상, 냉각수 온도차 3 °C. AI 가 스트레이너를 반박하고 **정지 후 화학 세정**을 고른다(온라인 전환은 "원인과 맞지 않음"). 펌프 정지 → 정비 모드(LOTO) → 세정 → 해제 → 재기동 → 110 → 68 °C. 보고서에 예상 정지 2.4 h 대비 실제 3.7 h(설비 시간) 차이가 그대로 나온다.

### 시나리오 2 — 교반기 진동(회전기계)
1. "시나리오 2 · 이상 발생" (베어링 마모): 전류가 먼저 상한을 넘고 진동이 뒤따른다(CEP 경보).
2. 카드: 첫 경보 시점에 전류 13.7 A·진동 2.2 mm/s(전류가 먼저) → 베어링 지지·축 정렬 반박. 권고 "배치 끝까지 운전 후 교체"(−449만원) vs "지금 교체"(−496만원). 뒤집힘: 고착 위험 비용률 90→135, 배치 폐기 손실 210→157.5, 남은 배치 1.5→2.25 h 이면 "지금 교체".
3. **반려 시연**: "고착 위험이 더 크다, 지금 멈추는 안으로" 사유로 반려 → "AI 분석" 다시 → 새 카드가 사유대로 "지금 교체"를 고르고 1위와의 차이(약 45만원)를 밝힌다 → 승인 → 정지·LOTO·베어링 교체("외륜 박리·윤활 탄화")·재기동.

**변형(축 정렬 불량)** — 진동만 크게, 전류는 상한 아래, CEP 없음 → 정렬 지지·베어링 반박 → "배치 후 정렬"(−247만원, 1위). 배치 대기(설비 1.5 h = 실제 9초) → 정지·LOTO·정렬("편차 0.45 → 0.02 mm")·재기동.

### 시나리오 3 — 반응기 고압·인터록(계기·배출)
1. "시나리오 3 · 이상 발생" (PT-101 드리프트): 지시 6.8 barg 로 **인터록이 펌프를 멈춘다**. 독립 계기 PT-102 는 3.2 barg.
2. 카드: 첫 경보 때 PT-101 6.41 vs PT-102 5.20 barg(차 1.2 bar) → 드리프트 지지. "인터록 우회 재기동"(−25.5만원)은 손익 1위지만 **규정으로 제외**, 교정안(−57.8만원) 선택.
3. 승인 → 정비팀 비교 교정(소견 "+3.6 bar 편차, 교정") → **운전원이 FUXA 에서 인터록 리셋**(AI 는 리셋할 수 없다, 화면에 "운전원 조치 필요") → 펌프 재기동 → 두 계기 일치·공급 재개 30초 → 보고서.

**변형(배출 밸브 고착)** — 실제 고압(두 계기 7.53/7.50 barg). 펌프가 멈추면 현재값은 곧 정상처럼 보이므로 AI 는 트립 전 값(배출 0.93 < 공급 3.76 m³/h·액위 79 %)으로 밸브 고착을 지지하고, "순간 과압"은 트립이 가린 것이라 반박 → 밸브 분해 정비("스템 고착, 실제 개도 15 %") → 운전원 리셋 → 재기동.

## 3. 실패 가지(해피패스가 아님을 보이는 법)
- **원인을 틀리면**: 정비팀이 "부품 정상, 교체 안 함" 소견을 내고 계획이 멈춘다(원인 불일치). 이때 정비 모드를 켠 뒤라면 정비팀이 **중단 정리**(분해 부위 복구·LOTO 해제, 설비는 정지 인계)를 하고 끝낸다 → 보고서 → "AI 분석"을 다시 누르면 같은 사건의 소견을 근거로 다른 대안을 고른다(이미 멈춘 설비라 "배치 후" 대안은 규칙으로 제외). 시험 도구 `python tests/e2e/maintenance_scenarios.py s2m` 이 이 가지를 재현한다(시험용 대응안으로 일부러 틀린 계획을 승인).
- **규칙**: 손익 1위라도 규정(인터록 우회·상한 초과 운전·진동 영역 D·예비품 없음)에 걸리면 제외된다.
- **사실값이 바뀌면**: `enterprise.fact`(예: 베어링 재고 0)를 바꾸면 같은 사건에서 다른 권고가 나온다.

## 4. 문제가 생기면
| 증상 | 확인 | 대처 |
|---|---|---|
| 카드가 안 나옴 | AI 화면 "AI 처리 과정" 실패 표시 | "AI 분석" 버튼으로 다시. 실패 사유가 화면에 남는다 |
| 카드가 왔는데 화면은 그대로 | 공정 흐름에서 「담당자 검토」가 빛남 | 보던 단계는 자동으로 바뀌지 않는다. 「현재 처리 단계 보기 · 담당자 검토」를 누른다 |
| 승인 뒤 단계가 "실패" | 단계 사유(모드·정비 모드·인터록) | 운전 모드 REMOTE_AUTO 확인. 결과 불명확한 명령은 다시 보내지 않는다(설계) |
| 시나리오 3 이 "운전원 조치 대기" | FUXA 인터록 상태 | FUXA 에서 인터록 리셋(압력이 5.2 barg 아래일 때만 받는다) |
| 다음 시나리오가 이전 사건에 붙음 | 사건 목록 | 초기화 뒤 30~40초 기다린 다음 버튼 |
| 사건 목록에 흐린 사건이 많음 | "참고 신호 숨기기" | 한계 이탈 없이 통계 급변만 있는 사건(회복·재기동 과도기)이다. 기본으로 숨긴다. AI 는 이런 사건을 자동 분석하지 않는다 |
| 예상 대비 실적 차이가 큼 | 보고서 KPI 표 | 정상이다. 단계마다 작업 요청이 수 초 걸리고 배속(600) 때문에 설비 시간으로는 길어진다. 숨기지 않고 실측대로 보인다 |
