# 가치 틀 (Value Frame)

이 애플리케이션은 **기술이 아니라 가치로** 구성한다. 기술은 해마다 바뀌므로, 틀은 "무엇을 가능하게 하는가"로 고정하고 기술은 그 가치를 올해 구현하는 **교체 가능한 수단**으로 둔다. 실측도 가치 단위로 하여, 기술을 바꿔도 같은 잣대로 다시 잰다.

- 설명은 재료(특정 공정 값·화학 내용)가 아니라 가치와 그 가치를 내는 구조로 한다.
- 새 설비·새 고장 유형은 **코드 수정 없이 온톨로지와 매뉴얼 추가만으로** 처리돼야 한다(V5).
- 기준 문서: AGENT_BRIEF_FINAL. 이 문서는 FINAL의 Gate·시나리오·CQ를 가치에 묶는 상위 틀이다.

## 가치와 측정

| # | 가치 (해마다 유지) | 합격을 판단하는 질문 | 지표 (가치 단위) | 관련 FINAL 항목 |
|---|---|---|---|---|
| V1 | **이상을 놓치지 않고 제때 알아챈다** | 주입한 이상을 빠짐없이, 거짓 없이, 늦지 않게 알리는가 | 탐지율·오탐 수·탐지 지연 p95·재시작 후 유실/중복 | S01~S13, G8, M1~M4 |
| V2 | **알람의 원인을 근거와 함께 찾는다** | 알람에서 원인 후보를 추론하고, 각 후보에 관측·문서 근거를 붙이며, 근거 없는 확정을 하지 않는가 | 원인 후보 정답률(Top-1/Top-3), 근거 링크 완전성, 근거 없는 확정 수(=0), 추론 시간 | CQ04~CQ07·CQ12, S25 |
| V3 | **상황에 맞는 조치 절차를 찾아 해석해 준다** | 원인·상황의 의미로 맞는 매뉴얼 절을 찾고, 절차를 현재 상태에 맞게 해석해 허용된 조치로 연결하는가 | 절 검색 정답률(Recall@k), 해석 정확도(단계·전제조건 대조), 허용 목록 밖 조치 제안 수(=0) | CQ03, CQ05 |
| V4 | **사람 승인 아래 안전하게 조치한다** | 반려·인터록·조건 변화·실패·중복에서 설비를 잘못 움직이지 않고 모든 결정이 기록되는가 | G1~G7 통과, 명령 왕복 시간, 감사 체인 완전성 | S14~S22, G1~G7, CQ08~CQ11·CQ14·CQ15 |
| V5 | **새 설비·고장이 생겨도 의미로 확장된다** | 코드 변경 0줄로 온톨로지·매뉴얼만 추가해 새 고장 시나리오를 V1~V4 수준으로 처리하는가 | 추가 시나리오의 V2·V3 지표, 코드 변경 줄 수(=0), 추가에 든 시간 | 신규 시나리오(확장 시험) |
| V6 | **적은 자원·단순한 구성으로 유지된다** | 같은 가치를 더 적은 자원과 부품으로 내는가 | 메모리·CPU, 컨테이너 수, 설정·코드 줄 수, 라이선스·비용 0원 | M5~M7, G9, G10 |

## 기술은 이렇게 들어간다

각 가치에 대해 "올해의 구현"과 "그 선택의 실측 근거(EXP)"를 적는다. 기술을 바꿀 때는 같은 지표로 다시 재서 비교한다.

| 가치 | 올해 구현 (후보) | 선택 근거 |
|---|---|---|
| V1 | 스트림 패턴 탐지(Flink SQL / Python 서비스), 메시지 경로(MQTT 브로커, 로그형 백본) | EXP-110대, EXP-130대 |
| V2 | 온톨로지 그래프 추론(증상 → 고장모드 → 원인 → 확인 관측) | 온톨로지 V2·V3, CQ 응답률 |
| V3 | 의미 검색(임베딩) + 온톨로지 연결 + 에이전트 도구 | 검색·해석 실측 |
| V4 | 승인 워크플로(HITL), DB 제약 기반 재검사·중복 방지, 인터록 | G1~G7 |
| V5 | 온톨로지 스키마의 플랜트 독립성, 문서 적재 파이프라인 | 확장 시험 |
| V6 | 구성 단순화(클린시트 비교) | EXP-320, M5~M7 |

## 미정

- V2·V3의 정답 세트(어떤 알람에 어떤 원인·어떤 절이 정답인가)는 온톨로지·매뉴얼 설계와 함께 **구현 전에** 고정한다(결과를 보고 맞추지 않는다).
- V5 확장 시험의 새 고장 유형은 설계 문서에서 정한다.
