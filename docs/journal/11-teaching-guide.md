## 11.1 대상과 선수 지식

| 대상 | 선수 지식 | 이 과정에서 얻는 것 |
|---|---|---|
| 제어/계장 엔지니어 | PLC, Modbus, P&ID | IT 스택(Kafka/Flink)과의 접점, 데이터 파이프라인 설계 |

**공통 선수 조건**: Docker Compose 사용 경험, 리눅스 명령줄, Python 또는 Java 읽기

## 11.3 각 차시의 공통 구조 제안

```
1. 이 계층이 없으면 무엇이 안 되는가  (10분)
2. PDF/표준이 말하는 것               (20분)
3. 실제로 해보면 다른 점              (30분)   ← 함정 사례
4. 실습                               (80분)
5. 검증 — 어떻게 "됐다" 고 말할 것인가 (30분)
6. 정리와 다음 계층 예고              (10분)
```

3번(함정)과 5번(검증)이 이 교재의 차별점입니다.
일반적인 튜토리얼은 성공 경로만 보여줍니다.

## 11.4 평가 항목 제안

### 실습 평가 (구축 능력)

| 항목 | 배점 | 확인 방법 |
|---|---|---|
| 시뮬레이터 Modbus 읽기/쓰기 | 10 | `make verify S=edge` |
| EdgeX 프로파일 작성 및 기동 | 15 | core-data 이벤트 증가 |
| Kafka 스키마 정규화 | 10 | `make verify S=backbone` |
| Flink SQL 탐지 3종 | 20 | 잡 3개 RUNNING + 시나리오 탐지 |
| ONNX 잡 구동 | 15 | 추론 지연 < 5ms |
| 저장/감시 이원화 | 10 | Prometheus 에 센서 태그 0개 |
| FUXA 양방향 제어 | 20 | `make verify S=scada` |

### 이해도 평가 (설계 판단)

1. PDF 의 "EMQX → Kafka 직결" 이 오픈소스에서 불가능한 이유와,
   선택 가능한 대안 3가지의 장단을 설명하시오.
2. `raw` 와 `clean` 토픽을 분리하는 것이 왜 감사 추적에 필요한가?
   단일 토픽에 `quality` 필드만 추가하는 방식과 비교하시오.
3. 롤링 Z-Score 가 정상 운전 중 오탐을 내는 구조적 이유와,
   지속성 조건 외의 해결책 2가지를 제시하시오.
4. 오토인코더 학습 데이터에 운전 변동이 필요한 이유를 설명하고,
   변동 폭이 너무 클 때 생기는 문제를 서술하시오.
5. Prometheus 에 센서 데이터를 저장하면 안 되는 이유를
   카디널리티 개념으로 설명하시오.

## 11.5 실습 환경 준비

### 최소 사양

| 항목 | 요구 |
|---|---|
| Docker 메모리 | 12 GB 이상 (파이프라인 9.1 GB + 여유) |
| 디스크 | 20 GB (이미지 약 6 GB + 데이터) |
| CPU | 4코어 이상 |
| 아키텍처 | arm64 / amd64 모두 가능 (전 이미지 멀티아치) |

### 사전 준비 (강사)

```bash
# 이미지 미리 받아두기 — 강의 중 다운로드 대기 방지
docker compose pull
docker compose build

# 모델 미리 학습해 볼륨에 넣어두기 (학습 90초 절약)
docker compose run --rm model-trainer
```

### 경량 모드

시간이 부족하거나 사양이 낮으면 EdgeX 를 건너뜁니다.

```bash
make lite     # 컨테이너 19개, 메모리 약 6 GB
```

3차시(EdgeX)만 시연으로 대체하고 나머지는 동일하게 진행할 수 있습니다.

## 11.6 이 교재가 다루지 않는 것 (후속 과정 제안)

| 주제 | 이유 |
|---|---|
| 고가용성 (Kafka 다중 브로커, Flink HA) | 단일 노드 구성. 별도 과정 필요 |
| 보안 (TLS, 인증, EdgeX Secret Store) | 데모는 평문. 실 운영 필수 |
| 대규모 부하 (수만 TPS) | 파티션·슬롯 확장 설계가 별도 주제 |
| 실제 PLC 연동 | 시뮬레이터로 대체. Modbus 표준 준수라 주소만 바꾸면 가능 |
| MLOps (모델 재학습 자동화, A/B) | 오프라인 학습 1회만 다룸 |
| OPC-UA | EdgeX device-opcua 로 확장 가능하나 미포함 |

## 11.7 자료 인용 시 주의

- 모든 로그의 타임스탬프는 구축 당시(2026-09-16)의 것입니다.
- 포트는 `.env` 의 27000 대역 기준이며, 수강생 환경에 맞춰 바꿔야 합니다.
- 버전은 EdgeX 4.0.0 / EMQX 5.8.6 / Kafka 3.9.0 / Flink 1.20.1 기준입니다.
  상위 버전에서는 [07-troubleshooting](07-troubleshooting.md) 의 일부 함정이
  해소되었거나 새로운 것이 생겼을 수 있습니다.
- 실측 수치는 Apple Silicon / Docker 메모리 31 GB 환경 기준입니다.
