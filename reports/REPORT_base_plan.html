4-1이름 풀이와 "왜 이렇게"

OT · DMZ · IT
공장(기계를 움직이는 쪽) · 둘 사이 중간 구역 · 사무실(분석·업무·AI 쪽)
PLC
설비에 전선으로 연결된 제어기. 값을 읽고(↑) 명령을 내보내며(↓) 인터록을 지킨다
엣지 게이트웨이
PLC의 통신 방식(Modbus)을 공통 방식(MQTT)으로 바꿔 브로커에 올린다. 요청 수신도 여기서
MQTT 브로커
프로그램끼리 값을 주고받게 하는 메시지 중계 프로그램(Mosquitto). OT용 하나, DMZ용 하나
UNS
공장 전체의 현재 값을 브로커 한 곳에 이름 규칙대로 모으는 현업 방식
SCADA/HMI
운전원이 보는 공장 화면(FUXA). 브로커에서 값을 받는다
DMZ 게이트웨이
IT에서 공장으로 가는 요청을 경계에서 검사하는 프로그램(우리가 만듦)
히스토리언
시간 순 공정 기록 저장소. DMZ에는 사본(InfluxDB)을 둔다
Bento
데이터를 받아 다른 곳으로 옮기는 운반 도구(DMZ 브로커 → Kafka 등)
Kafka
들어온 데이터를 순서대로 저장해 여러 프로그램이 각자 읽게 하는 이벤트 스트리밍
Flink
Kafka의 데이터를 계속 읽으며 이상을 찾는 스트림 처리(규칙·패턴·학습 모델)
Grafana · Prometheus
사무실에서 보는 추세 대시보드 · 서버·프로그램 감시
PostgreSQL · Neo4j
업무 기록(요청·승인은 추가만) · 설비·고장·매뉴얼 관계 지도
Pilot
이상 사건 → AI 조사 → 담당자 승인 → 조치 요청 → 결과 확인을 잇는 업무 서비스(우리가 만듦)
LiteLLM
AI 모델을 부르는 단일 관문(GCP)
라우터
구역 경계의 방화벽. 먼저 연 쪽이 허용된 방향일 때만 통과
MQTT 브로커가 왜 둘인가OT 브로커는 공장 안끼리, DMZ 브로커는 바깥과의 접점이다. 공장 안에 하나만 두면 IT가 공장 안으로 들어와야 하고(규칙 위반), DMZ에 하나만 두면 DMZ가 끊길 때 공장 화면·조작이 멈춘다. 그래서 OT 브로커가 DMZ 브로커로 먼저 연결해 필요한 것만 주고받는다(지침 p.11·p.19).
왜 PLC를 거치나설비의 모터·밸브는 PLC 출력에 연결돼 있어 기계를 움직이는 길은 PLC 하나다. 인터록도 PLC에 있다. 실측: 승인부터 설비 반영 확인까지 1.4~1.6초.
DMZ 게이트웨이가 왜 필요한가지침이 IT/OT 경계에서 알려진 형식만 통과시키라고 한다(p.17). 없으면 IT가 DMZ 브로커에 직접 쓸 권한을 가져야 한다. 이 역할만 하는 무료 제품이 없어 직접 만들었다(Bento는 만료 표시·즉시 거절 불가, 실측).
대시보드는 왜 IT에 있나현업도 사무실 대시보드는 IT에 두고 공장이 아니라 DMZ의 기록 사본을 본다(지침 p.19). 운전원 화면은 OT의 SCADA/HMI(FUXA)다.
