SCADA 베이스 설계 — 2026 현업 조사에서 우리 아키텍처까지

프로토타입 시스템 아키텍처가 2026년 제조 현업과 맞는지 보려고 현업을 조사했다. 현업이 쓰는 구조·흐름·스택을 확인하고, 비용·라이선스·도커·현업 사용 근거·용도를 기준으로 칸마다 제품을 골라 우리 아키텍처를 정했다. 이 문서는 계획과 근거다. 새 베이스의 실측 결과는 아직 없다.

한눈에 — 이 문서의 이야기

  1. 1왜 조사했나프로토타입 아키텍처를 2026 현업 기준으로 점검한다
  2. 2현업은 이렇다OT·DMZ·IT 세 구역, PLC가 최종 판단, 데이터는 공장이 밀어낸다
  3. 3우리 기준현업 주류 → 비용 0·라이선스·도커·계열 유지 → 경량화
  4. 4칸마다 선택현업과 같은 제품 7칸, 현업이 상용이라 무료로 대신 5칸, 맞는 무료 제품이 없어 자체 1칸(등록부·승인·알람)
  5. 5우리 아키텍처설비부터 업무·승인까지 10개 층 한 장
  6. 6확정 범위L1~L4는 표준 근거 강함, 외부 연결은 원칙만 표준, 방법은 조사 중

원본 폴더 lecture-iiot-scada는 고치지 않는다. 복사본에서 원본 V1 코드를 출발점으로 바꾸며 원본 기능은 잃지 않는다. 순서는 베이스 → 설비 확장(다수·OPC UA) → 시나리오·온톨로지이고, 이후 피지컬 AI에 쓴다.

1. 왜 조사했나 — 무엇을, 어떻게

학생이 배우는 프로토타입(원본 V1)이 2026년 제조 현업의 구조와 스택에 맞는지 보고, 맞지 않는 곳을 현업 기준으로 고치기 위해서다. 우리 구조를 정답으로 두지 않고 "우리는 이렇다, 현업은 어떤가"로 물었다. 비교 대상으로 참조 설계서 v3(다른 팀이 실제 구축·실행)와 우리 구조도 PDF를 함께 보냈다.

  1. 구조12번층·길·망·확장·AI 연결. 표준 원문 중심(출처 39)
  2. 세부13번토픽·명령·알람·저장·확장 결정 29줄(출처 90, 62곳은 검색 요약)
  3. 스택14번칸마다 현업 주류 제품·버전·라이선스·도커 이미지
  4. 무료 대체품15번현업이 상용인 PLC·엣지·화면의 무료 후보 비교
  5. 외부 연결16번 · 조사 중밖으로 보내기·설비 쪽으로 보내기 방법과 사용 정도
근거 규칙근거마다 표준·독립 분석·벤더·사례·재단을 표시했다. 벤더 한 곳의 말로 "현업 주류"라고 쓰지 않았다.
원문 여부원문을 읽었는지, 검색 요약만 봤는지 구분했다. 못 찾은 것은 "찾지 못함"으로 남겼다.
조사 범위의 한계한국 법규는 조사하지 않았다. 유료 표준 본문(IEC 62443, ISA-112)은 목차·해설만 봤다. 채택률 수치는 공개 자료에 없다.

  • IT에서 OT로 바로 가는 길은 없다. 명령은 사람 승인 → 검증 통로 하나 → 제어기가 최종 판단한다.

현업 흐름

근거 원문: 12-industry-structure.md · 13-industry-detail.md(세부 근거 90곳 중 62곳은 검색 요약만 확인, EEMUA 191·ISO 14224 등 핵심 표준 원문은 미확인)

데이터 ↑ 설비 → 제어기(PLC) → 엣지(프로토콜 변환, 끊기면 저장 후 전송) → MQTT 허브(UNS, 공장/구역/라인/설비 이름 체계) → DMZ에서 위로 복제 → Kafka형 장부·이력 저장 → 분석·대시보드·AI(OT가 밀어낸 데이터를 읽기만). 주기 샘플링과 변화 필터, 값마다 시각과 품질(끊기면 STALE).
명령 ↓ 운전원은 SCADA 화면 → 제어기. 외부·AI 명령은 사람 승인 → DMZ 검증 통로 하나 → 제어기가 최종 판단(NAMUR NE 178). 확인은 제어기 응답과 바뀐 값 두 겹. IT에서 OT로 바로 가는 길은 없다.
알람 공정 알람은 제어기·SCADA가 만들고 수명주기(인지·억제)를 가진다. 분석 결과는 ISA-18.2의 "경고(alert)"로 알람 목록과 따로 둔다. 서버·컨테이너 경보는 인프라 담당에게만 간다.
AI 위치 현업에 "AI 층"은 따로 없다. ML 이상 탐지는 주로 L1~L3(PLC·엣지·SCADA 쪽), LLM·에이전트는 L4~5(OT 밖)에서 OT가 브로커·감사되는 버퍼로 내보낸 데이터를 읽기 전용으로 쓴다(CISA 등 9개 기관 AI-OT 지침 2025 표1·p.15·p.19). "Kafka를 거쳐 AI로"는 이 원칙과 UNS+Kafka 트렌드를 합친 구성이고, 표준이 제품을 지목하지는 않는다. 지식 그래프·LLM 에이전트의 현장 운영 비율은 설문 수치가 없다.
저장 이력 정본은 IT 한 곳, OT에는 화면용 단기 추세만. 명령·승인·감사 기록은 추가만 한다.
설비 추가 층은 그대로. 설비 종류 모델과 설비 목록(등록부)에 더하면 이름·토픽·키·규칙이 같은 ID로 이어진다.

3. 우리가 고르는 기준

현업을 그대로 옮길 수는 없다. 학생마다 PC 한 대(도커 7.6 GB)에서 비용 없이 돌려야 한다. 그래서 칸마다 아래 순서로 걸렀다.

  1. ①
    현업에서 주로 쓰는 것독립 분석·설문·표준에 나온 주류 제품. 무료 본체가 있으면 그대로 쓴다.
  2. ②
    통과해야 하는 관문비용 0 · 금지 라이선스 아님(BSL·SSPL·TSL·RCL·체험판·상용 기능) · 공식 도커 이미지 · 제품 계열이 계속 개발됨. 판마다 있는 지원 종료일은 제외 이유가 아니다(학기마다 같은 계열 최신 판으로 올림).
  3. ③
    경량화현업 수준을 유지한 채 가벼운 판·설정·선택 기능·중복 합치기로 줄인다. 층을 빼지 않고, 원본보다 나빠지면 쓰지 않는다.

현업 주류를 그대로 못 쓴 이유(관문 ②)

대표 사례 — 엣지: 공장용인가, 범용인가

EdgeX 4.0.2 · 공장용 엣지 플랫폼장치 등록부·명령 창구·끊김 시 저장을 기본 제공. 도입 기업 사례(Eaton·Wipro 등). 산업 논문 33편. 컨테이너 약 10개.
Node-RED 5.0.x · 범용 연결 도구무료 중 현업 사용 근거가 더 많다(산업 논문 486편, OpenJS 재단, Opto 22 산업 제어기 기본 탑재). 가볍다. 장치 등록부·명령 API·끊김 저장은 없어 등록부 생성 흐름으로 채운다.

결정: 조립 때 둘을 같은 가상설비·PLC에 붙여 나란히 잰다. 합격 조건은 12태그 누락 0, 화면 명령이 PLC까지 가고 응답이 돌아옴, 10초 단절 뒤 복구·유실이 원본(7.3초·120 태그·초)보다 나쁘지 않음, 등록부에서 설비 한 대를 자동 추가함이다. 둘 다 합격이면 Node-RED, 하나만이면 그쪽. 메모리는 비교값으로만 쓴다.

이 시스템은 이후 피지컬 AI에 쓸 계획이다. 다만 피지컬 AI는 조사하지 않았으므로 어느 칸의 선택 근거로도 쓰지 않았다. 확장의 받침은 승인 → 검증 통로 → PLC 최종 판단 길과 설비 등록부다.

5. 그래서 우리 시스템 아키텍처는 이렇다

근거 원문: 12-industry-structure.md(층 B0~B13·길 목록) · 13-industry-detail.md(세부) · 14-industry-stack.md(제품·버전)

2장의 현업 구조·흐름과 4장의 칸별 선택을 한 장에 합친 그림이다. 아래 L1 설비에서 위 L10 업무·승인까지 10개 층이고, 색 띠가 망 구역(OT·DMZ·IT)이다. 번호 순서대로 따라가면 흐름이 된다.

구역 뜻: OT(운영 기술)는 공장에서 기계를 실제로 움직이는 쪽(설비·PLC·SCADA 화면)이다. 멈추면 기계가 서므로 안전과 계속 도는 것이 먼저다. IT(정보 기술)는 사무실 쪽(저장·분석·AI·업무)이다. DMZ는 둘 사이 완충지대다. 데이터는 OT가 밀어서 내보내고, IT에서 기계로 바로 가는 명령 길은 없으며, IT가 멈춰도 공장은 돈다.

데이터가 올라가는 길(D) 알람·사건(A) 명령이 내려가는 길(C, M) 읽기·생성(R, G) 새로 = 원본 V1에 없던 것

흐름 순서

데이터 ↑
  1. D1PLC가 설비 값을 Modbus로 읽는다
  2. D2엣지가 PLC의 값·상태·ACK를 읽는다
  3. D3엣지가 시각·품질을 붙여 허브에 발행
  4. D4FUXA가 허브를 구독해 현재값 표시

  6. D6Kafka raw·상태·ACK 토픽에 기록
  7. D7Flink가 raw를 읽는다
  8. D8Flink가 clean·score·alerts를 Kafka에 쓴다
  9. D9이력 적재가 Kafka를 읽고

설비 추가: 층은 그대로다. 설비 등록부(G)에 한 줄 더하면 엣지 설정·토픽·Kafka 키·Flink 적용 범위·Neo4j 노드가 배포 전에 함께 만들어진다. 플랫폼 감시(Prometheus + Alertmanager·cAdvisor·kafka-exporter)는 전 구역 지표를 모아 인프라 담당에게만 보낸다.

6. 어디까지 확정이고, 어디부터 원칙만 있나

L1~L4 · OT(설비·PLC·엣지·허브·화면)구조 확정. 구역·층 구조는 표준 근거 강함(Purdue·NIST·CISA). 단 UNS 허브는 업계 트렌드(채택 통계 없음)이고, 엣지 제품은 조립 때 실측으로 정한다.
L5 · DMZ원칙은 표준 권고, 법은 아님(외부 접근은 DMZ에서 끝나고 OT가 밀어낸다, 쓰기 요청은 검증 통로 하나 → PLC 최종 판단). 방법은 표준이 하나로 정하지 않았다.
L6~L10 · IT(장부·탐지·저장·AI·업무)제품은 현업 1위 오픈소스. 배치와 연결 방식은 업계 동향과 우리 설계(조사 12번 제안)다.

층별 근거

"IoT-SCADA"는 표준의 층 이름이 아니다. 현업 표준 층은 Purdue 모델(L0 현장 장치, L1 PLC, L2 SCADA·HMI, L3 히스토리언·MES, L3.5 DMZ, L4~5 기업망)이다.

공통 원칙은 "OT가 밖으로 밀어내고, IT에서 OT로 직접 들어오는 길은 없다"(표준, 근거 강함)이다. "UNS는 히스토리언을 대체하지 않는다"(IT/OT Insider). 우리는 규칙을 지키고 방법은 ③을 쓴다(원본 V1 뼈대가 ③이고, 규칙을 지키면 현업과 맞다는 조사 12번 판단, 무료로 구성 가능). ③은 "현업 추세"이지 "주류"로 확인된 것은 아니며, 수업에서 ①이 표준 기본 배치임을 함께 설명한다.

외부에서 설비 쪽으로 보내는 흐름

표준이 정한 것바깥(업무 시스템·AI·최적화)의 쓰기 요청은 검증 통로 하나를 거치고, 받을지는 제어기가 최종 판단한다(NAMUR NE 178). IT에서 OT로 바로 가는 길은 없다(CISA). 사람 없는 AI 제어는 제한한다(CISA 2025).
우리 설계(표준이 정하지 않은 부분)사람 승인 → Kafka 명령 요청 → DMZ 게이트웨이 검사 → 허브 cmd → 엣지 → PLC 최종 검사(5장 C1~C7). "명령을 Kafka로" 보내는 현업 근거는 아직 찾지 못했다. 게이트웨이 오픈소스 제품도 없어 자체 코드다.

법으로 "반드시 사본"을 요구하는 것은 아니다. 조사에서 찾은 문서 중 법령은 21 CFR Part 11(감사 기록) 하나이고, 나머지는 표준·지침·권고다. 조사한 범위 안에서는 "사이트 히스토리언을 OT에 꼭 둬야 한다"는 요구 문장도 없었다(13번). 한국 법규와 유료 표준 본문은 조사 범위 밖이다. 외부 연결 방법의 비교·사용 정도와 설비 쪽으로 보내는 방법은 조사 16번(의뢰서 §9) 결과로 이 장을 채운다.

  • AI 층의 판단 로직(에이전트·온톨로지·매뉴얼 검색). 설비에 닿는 연결 부분만 새 명령 길로 바뀐다
  • 수업 자료가 쓰는 계측 토픽 edgex/telemetry
  • 확인 스크립트 scripts/verify.py가 검사하는 내용(검사 방법은 새 구조에 맞게 바뀜)

9. 근거가 약한 곳 · 확인 못 한 것

  • "현업 주류"의 근거는 표준·독립 분석·설문이다. 이름 있는 공장의 내부 구성과 채택률 수치는 공개 자료에 없다.
  • 무료 제품끼리의 점유율 설문은 없다. 논문 수·대학 수업·재단·개발 활동으로 비교했다.
  • 세부 결정 조사는 출처 90개 중 62곳이 검색 요약만 본 것이다. 핵심 근거(EEMUA 191, ISO 14224 등)는 원문 미확인이다.
  • 새 베이스의 메모리 합계는 재지 않았다. 잰 칸만 약 4,960 MiB, 미측정 5칸(PLC·엣지·게이트웨이·AI 백엔드·승인).
  • Node-RED는 읽기 경로만 전에 쟀다(1,356/1,356). 쓰기·단절 복구·등록부 생성은 엣지 실측으로 확인한다.
  • 원본에 안정화 수정 5가지를 얹어 확인했을 때 결측 주입 관련 검사 3개가 실패했다. 원인 미확인, 조립 때 처리.
  • 외부 시스템 연결 방법의 비교·사용 정도, 외부에서 설비 쪽으로 보내는 방법, "명령을 Kafka로"의 현업 근거는 조사 16번에서 확인 중이다.
  • 한국 법규와 유료 표준 본문(IEC 62443, ISA-112)은 조사 범위 밖이다.
