경남대 제조 AI 과정 · IIoT·SCADA 실습 시스템 · 2026-09-29

SCADA 베이스 설계 — 현업 조사로 정한 구조와 스택

학생이 배우는 시스템을 2026년 제조 현업에서 주로 쓰는 구조와 스택에 맞춘다. 현업 조사 네 건(구조·세부·스택·무료 대체품)으로 무엇을 왜 쓰는지 정했고, 조립과 검증은 다음 단계에서 한 번에 한다. 이 문서는 계획과 근거다. 새 베이스의 실측 결과는 아직 없다.

한눈에

기준① 현업에서 주로 쓰는 것 ② 비용 0·라이선스·도커·제품 계열 유지 ③ 경량화(현업 수준은 유지). 학생 PC 한 대(도커 7.6 GB)에서 돈다.
원본은 그대로원본 폴더 lecture-iiot-scada는 고치지 않는다. 복사본에서 원본 V1 코드를 출발점으로 바꾸며, 원본 기능은 잃지 않는 것이 기준이다.
순서베이스(구조·스택 확정 완료 → 조립 → 검증) → 설비 확장(다수·OPC UA) → 시나리오·온톨로지. 이후 피지컬 AI에 쓴다.

흐름

데이터 ↑ 설비 → PLC → 엣지 → Mosquitto → DMZ 복제 → Kafka → Flink 탐지·InfluxDB 저장 → Grafana·AI. 값마다 시각과 품질(끊기면 STALE)을 붙인다. 토픽은 공장/구역/라인/설비/종류/태그.
명령 ↓ 운전원: FUXA → cmd → 엣지 → PLC 검사 → 설비. AI 제안: 사람 승인 → Kafka 명령 → 게이트웨이 검사 → 엣지 → PLC 최종 검사. 확인은 PLC 응답과 바뀐 값 두 겹. AI·화면의 직접 쓰기는 없다.
알람 공정 알람은 PLC·화면이 만들고, Flink 결과는 "분석 경고"로 따로 보여 준다. 반복 경고는 사건 하나로 묶어 AI가 원인을 본다. 서버 이상은 인프라 담당에게만 간다.
설비 추가 층은 그대로. 설비 등록부(종류 모델 + 설비 목록)에 한 줄 더하면 엣지 설정·토픽·Kafka 키·탐지 범위·온톨로지 노드가 함께 만들어진다.

5. 주요 결정과 이유

근거 원문: 14-industry-stack.md · 15-free-options-compare.md

엣지는 실측으로 정한다Node-RED와 EdgeX를 같은 설비에 붙여 12태그 누락, 명령→PLC→응답, 10초 단절 복구·유실, 설비 자동 추가를 합격 조건으로 잰다(메모리는 비교값). 둘 다 합격이면 Node-RED(가볍고 더 많이 쓰임), 하나만이면 그쪽.
버전 규칙제품을 빼는 경우는 개발이 멈췄거나 라이선스가 유료·제한형으로 바뀐 경우뿐이다. 판마다 있는 지원 종료일은 이유가 아니다. 학기마다 같은 메이저 안 최신 부 버전으로 올린다.
경량화의 뜻현업 수준을 유지한 채 가벼운 판·설정 조정·선택 기능 프로필·중복 합치기로 줄인다. 층을 빼지 않는다. 성능·안정성이 원본보다 나빠지면 쓰지 않는다.
피지컬 AI이 시스템은 이후 피지컬 AI(AI가 설비·로봇을 보고 움직이게 함)에 쓴다. 베이스에서 따로 더하지 않는다. 승인 → 검증 → PLC 최종 판단 길과 설비 등록부가 받침이다.

6. 원본에서 바뀌는 것 · 그대로인 것

바뀌는 것
  • 망 3구역(ot·dmz·it)
  • PLC 층 추가, 설비에 붙는 것은 PLC 하나
  • 쓰기 길 3개 → 수동 하나 + 검증 통로 하나
  • 결과 확인을 시뮬레이터 API 대신 PLC 응답으로
  • 설비 등록부 추가
  • MQTT 브로커 2개 → Mosquitto OT 허브 하나(DMZ 중계 방식에 따라 구역마다 하나), Telegraf 3개 → Bento
  • Kafka·Flink·InfluxDB·Grafana·Prometheus를 지원되는 판으로
  • 엣지가 Node-RED로 정해지면 수업의 EdgeX 차시가 바뀐다
그대로인 것
  • 원본 폴더 lecture-iiot-scada(수정하지 않음)
  • 가상설비 7대·센서 12개·고장 시나리오(배속 600은 원본에 더해 둔 기능)
  • 탐지 규칙(임계치·Z-Score·CEP)과 학습된 오토인코더 모델
  • AI 층의 판단 로직(에이전트·온톨로지·매뉴얼 검색). 설비에 닿는 연결 부분만 새 명령 길로 바뀐다
  • 수업 자료가 쓰는 계측 토픽 edgex/telemetry
  • 확인 스크립트 scripts/verify.py가 검사하는 내용(검사 방법은 새 구조에 맞게 바뀜)

8. 근거가 약한 곳 · 확인 못 한 것

  • "현업 주류"의 근거는 표준·독립 분석·설문이다. 이름 있는 공장의 내부 구성과 채택률 수치는 공개 자료에 없다.
  • 무료 제품끼리의 점유율 설문은 없다. 논문 수·대학 수업·재단·개발 활동으로 비교했다.
  • 세부 결정 조사는 출처 90개 중 62곳이 검색 요약만 본 것이다. 핵심 근거(EEMUA 191, ISO 14224 등)는 원문 미확인이다.
  • 새 베이스의 메모리 합계는 재지 않았다. 잰 칸만 약 4,960 MiB, 미측정 5칸(PLC·엣지·게이트웨이·AI 백엔드·승인).
  • Node-RED는 읽기 경로만 전에 쟀다(1,356/1,356). 쓰기·단절 복구·등록부 생성은 엣지 실측으로 확인한다.
  • 원본에 안정화 수정 5가지를 얹어 확인했을 때 결측 주입 관련 검사 3개가 실패했다. 원인 미확인, 조립 때 처리.
