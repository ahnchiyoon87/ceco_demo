# 관제 대시보드 디자인 기준

## 한 제품의 화면으로 보이게 한다

공정·이상 대응·지식의 모든 탭에 동일한 글자 위계, 여백, 카드, 버튼, 입력폼, 상태 표시, 포커스와 스크롤 규칙을 적용한다. 특정 화면만 예쁘게 고치고 다른 화면을 그대로 두는 것은 완료가 아니다.

공통 값은 `src/design-tokens.css`가 기준이다. 컴포넌트를 수정할 때 같은 의미의 값을 따로 추가하지 않고 공통 변수를 사용한다. 현재는 지식 작업과 설비 조작부터 적용 중이며 전체 컴포넌트 전환은 남아 있다.

| 요소 | 공통 기준 |
|---|---|
| 본문 / 보조 설명 / 입력 | 14 / 13 / 15px. 실행 결과·경고·출처를 작은 장식 글씨로 처리하지 않는다. |
| 줄 간격 | 1.7. 긴 설명은 문단으로 나누고 식별자는 줄바꿈한다. |
| 간격 | 4·8·12·16·20px 단위. 같은 계층은 같은 간격. |
| 카드 / 조작 요소 모서리 | 12 / 8px |
| 주요 버튼·입력 높이 | 최소 44px. disabled는 이유를 함께 알 수 있어야 한다. |
| 상태 | 대기·진행·검토 필요·완료·실패·연결 끊김을 색과 문구로 함께 구분한다. 연결 끊김을 작업 실패나 성공으로 바꾸지 않는다. |
| 선택 / 실제 진행 | 선택 강조는 사용자가 연 카드, 진행 강조는 실제 서버 상태. 둘을 혼동하지 않는다. |
| 빈 화면 | 무엇이 없는지와 가능한 다음 행동을 보여준다. 탭을 눌렀는데 빈 공간만 남기지 않는다. |
| 스크롤 | 페이지 스크롤을 기본으로 한다. 그래프·긴 목록만 필요한 범위에서 내부 스크롤. 자동 갱신은 사용자 위치나 선택을 빼앗지 않는다. |
| 키보드 | 버튼·입력·펼치기에 동일한 포커스 표시. 모달/패널은 닫은 뒤 원래 조작 위치로 복귀. |

## 공정의 어두운 화면

공정도는 설비 상태를 구별하기 위한 어두운 표면을 사용할 수 있다. 다만 글자 크기·카드 간격·입력 높이·상태 의미·포커스 동작은 밝은 업무 화면과 같다. 어두운 배경이라는 이유로 별도의 제각각인 UI를 만들지 않는다.

## 완료 확인

공정 / 사건 목록 / 조사 / 담당자 검토 / 실행 결과 / 원본 / 관계 후보 생성 / 후보 검토 / 게시 이력 / 그래프 / 연결 현황을 PC와 모바일에서 같은 기준으로 확인한다. 정상·빈 상태·긴 내용·오류·끊김·복구를 포함한다. 전체 검수 전에는 디자인 통일 완료라고 기록하지 않는다.
