# ceco_demo — AR-100 반응기 라인 · SCADA + AI 정비 데모

가상 반응 공정 한 줄을 공장(OT)·완충지대(DMZ)·사무(IT) 세 구역으로 나눠 돌리는 학생 수준의 예시 시스템입니다.
고장이 나면 탐지하고, AI가 원인을 분석해 정비 계획을 세웁니다. 담당자가 승인하면 단계별 작업 요청과 가상 정비팀의 수리로 설비가 회복되고, 작업 보고서가 남습니다.
모든 부품은 무료 공개 제품이고(LLM만 OpenAI API) 도커 컴포즈 한 벌로 뜹니다.

```text
가상설비 ─Modbus─ PLC ─Modbus─ 엣지(Node-RED) ─MQTT─ OT 허브 ═브리지═ DMZ 브로커 ─ IT 수집기(Bento) ─ Kafka ─ Flink(탐지)
                                                                                                   │
  AI 업무 도우미(에이전트·판단 엔진·정비 실행기) ← 사건 ← 업무 서비스 ←──────────────────────────────┘
        │ 승인된 작업 요청
        └→ PostgreSQL → Kafka → IT 수집기 → DMZ 게이트웨이(검사 1) → OT 수신기(검사 2) → PLC(검사 3) 또는 가상 정비팀
```

## 빠른 시작

```bash
# 1) 설정: 견본을 복사하고 CHANGE_ME 자리(비밀번호·토큰)를 각자 정한 값으로 바꾼다. .env 는 git 에 올리지 않는다
cp .env.example .env

# 2) AI 키: .gitignore 로 제외된 파일에만 둔다(커밋하지 않는다)
echo "OPENAI_API_KEY=..." > 5_ai/server/.env.local

# 3) 기동 — 데모 경로 전체(감시 부품 제외, 약 3 GB). 첫 기동은 빌드·모델 학습으로 약 5분
make up
make ps          # 전부 healthy 인지
make urls        # 접속 주소

# 인프라 감시(Grafana·Prometheus·cAdvisor·exporter·IT InfluxDB)까지 띄우려면
make up-full
```

| 화면 | 주소 | 용도 |
|---|---|---|
| **단일 포털** | **http://localhost:38180** | 한 화면에서 설비 상태·이상 발생·전체 흐름도·검토 의견·승인·정비·복구 결과 |
| FUXA 운전원 화면 | 포털의 **설비 제어 패널**에서 열기 | 아이디·비밀번호 입력 없이 운전원으로 자동 연결. 추가 운전 조작 · 운전 모드 · 인터록 리셋 |
| Flink | http://localhost:37081 | 탐지 잡 4개 상태 |
| Grafana · Prometheus | http://localhost:37030 · 37090 | `make up-full` 일 때만 |

포트·계정은 `.env` 한 곳에서 바꿉니다(견본 `.env.example`, `.env` 자체는 git 에 올리지 않음). 같은 PC에서 다른 큰 도커 스택과 함께 띄우면 메모리가 모자랄 수 있습니다. 데모는 단독 실행을 권합니다.

Windows에서는 `Start-Booth.cmd -SkipBuild`로 기동과 실제 데이터 경로·포털 조작 접점까지 확인합니다. 새 설치의 `.env`에는 `PORTAL_CONTROL_TOKEN`도 32자 이상의 소문자 16진수 비밀값으로 설정합니다. 현재 PC는 설정되어 있습니다. `portal-controls`는 사람용 이상 발생·초기화와 운전원 자동 로그인을 기존 호스트 공개 접점으로 연결하며, AI 백엔드에 설비 비밀번호를 주거나 IT→OT 방화벽 규칙을 추가하지 않습니다. 일반 브라우저에서 포털 주소 하나를 열면 됩니다. 제어 패널은 같은 주소 아래에서 실시간으로 연결되고, 비밀번호는 서버에만 있습니다. 별도 강사 화면 없이 포털에서 조작합니다.

[5분 부스 영상](docs/video/ceco-booth-5min.mp4)은 원본 문서·실제 지식 게시·온톨로지부터 냉각 이상 감지·에이전트·승인·정비·복구까지 보여 줍니다. 정확히 300초·1080p·무음이며 하단 한국어 자막 40개가 포함되어 있습니다. `python video/booth.py`는 이 전체 흐름을 새로 촬영합니다(실제 모델 호출·지식 게시·가상 설비 조작 포함). 기존 원본만 편집하려면 `python video/booth.py --render <timeline.json>`을 사용합니다. 원본 문서 렌더링은 로컬 Node.js와 웹의 설치된 marked 모듈을 사용합니다.

## 정비 시나리오

| 명령 | 고장 | AI가 가려야 할 것 |
|---|---|---|
| `make scenario-1` | 냉각수 스트레이너 막힘 → 반응기 온도 상승 | 유량↓·차압↑ → 스트레이너(온라인 전환·세척) |
| `make scenario-1v` | 재킷 스케일 | 유량·차압 정상, 냉각수 온도차 작음 → 정지 후 화학 세정 |
| `make scenario-2` | 교반기 베어링 마모 | 전류가 진동보다 먼저 → 베어링 교체(지금 / 배치 후, 손익 비교) |
| `make scenario-2v` | 축 정렬 불량 | 진동만 큼 → 축 정렬 |
| `make scenario-3` | 압력계 PT-101 드리프트 → 인터록 오트립 | 독립 계기 PT-102 와 불일치 → 비교 교정 + 운전원 리셋 |
| `make scenario-3v` | 배출 밸브 고착(실제 고압) | 두 계기 일치·트립 전 배출 유량↓ → 밸브 정비 |
| `make fault-clear` | 전체 고장 해제 | |

고장은 저절로 낫지 않고, 원인에 맞는 정비만 회복시킵니다. 원인을 틀리면 정비팀이 "부품 정상"으로 답하고 계획이 멈춥니다. 손익 1위라도 규칙(인터록 우회·상한 초과 운전 등)에 걸리면 제외됩니다.
자동 시험: `python tests/e2e/maintenance_scenarios.py s1 s1v s2 s2v s3 s3v s2m [--reject-first 사유]` (실제 LLM 호출, 경우마다 수 분).

탐지 계층만 따로 보는 고장 주입도 있습니다: `make fault-spike`(규격·인터록) · `fault-noise`(Z-Score) · `fault-bearing`(CEP) · `fault-drift`(오토인코더) · `fault-dropout`(결측 보간) · `fault-heater` · `fault-cooling`.

### 부스용 단일 운영 화면 (2026-10-13)

접속은 **http://localhost:38180** 하나다. 상황 선택과 「이상 발생」 후 경보 접수·분석은 자동으로 이어진다. 예상 원인과 권장 정비를 검토하고 의견을 작성한 뒤 「정비 승인」을 누르면 정비·30초 회복 확인·결과 기록까지 같은 화면에서 진행한다.
전체 흐름 그림은 항상 펼쳐져 있으며 승인·반려·자료 보완 경로와 실제 현재 상태를 표시한다. BPM 엔진 없이 저장된 처리 상태를 그리는 화면이다. 단계 그림을 클릭하거나 「프로세스 보기」·「AI 분석」·「기록 갱신」을 누를 필요가 없다. 원본 근거와 상세 기록만 접어 두었다.

왼쪽에 운영 현황·온톨로지·문서·지식·처리 이력 메뉴를 항상 표시한다. 분석 중에는 실제 도구와 현재 작업을 한두 줄로 갱신하며, 자세한 원인 판단·정비 대안·결과는 기존 상세 영역에서 확인한다. 메뉴를 이동해도 진행 중인 사건과 검토 의견을 유지한다.

온톨로지 지식 지도는 HYD 원격 main(6f350503)의 디자인을 기준으로 실제 지식 220개·관계 356개를 종류별 고정 열에 배치하고 직접 연결을 강조한다. 최신 부스 영상은 `docs/video/ceco-booth-5min.mp4`(4분 41초·무음·72px 중앙 한국어 자막)이며, 마우스·스크롤을 자연스럽게 움직이고 이상 수치와 복구는 실제 속도로 연속 재생한다.
